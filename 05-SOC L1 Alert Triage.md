# Alert Triage (Simple Notes)

# 1. Event

An **Event** is any activity that happens on a system.

### Examples

* User logs in
* File is downloaded
* Program starts
* Password is changed
* USB is connected

**Example:**

```text
User "John" logged into Windows.
```


# 2. Log

A **Log** is a record of an event.

Systems automatically save events into log files.

**Example:**

```text
10:15 AM
User John logged in successfully.
```


# 3. Alert

An **Alert** is a warning generated by a security tool when it detects suspicious activity.

Instead of checking millions of logs manually, analysts investigate alerts.


# How Alerts are Created

```text
Event
   ↓
System creates Log
   ↓
Logs sent to SIEM / EDR
   ↓
Detection Rule matches
   ↓
Alert Generated
   ↓
SOC Analyst investigates
```

# Security Tools

### SIEM (Security Information and Event Management)

Collects logs from many systems and generates alerts.

**Examples**

* Splunk ES
* Elastic



### EDR (Endpoint Detection and Response)

Monitors computers (endpoints) for suspicious activity.

**Examples**

* Microsoft Defender
* CrowdStrike



### SOAR (Security Orchestration, Automation and Response)

Automates security tasks and manages alerts.

**Examples**

* Splunk SOAR
* Cortex SOAR



### ITSM (IT Service Management)

Used to track incidents and tickets.

**Examples**

* Jira
* TheHive



# SOC Team Responsibilities

## SOC L2 Analyst

* Investigate complex attacks
* Perform deeper analysis

## SOC Engineer

* Configure SIEM & EDR
* Create detection rules
* Improve alerts



## SOC Manager

* Manage SOC team
* Monitor alert quality
* Ensure incidents are handled properly



# Alert Properties

## 1. Alert Time

When the alert was created.

Example:

```text
Alert Time : 15:35
Event Time : 15:32
```



## 2. Alert Name

Short description of the alert.

Examples

* Unusual Login Location
* Email Marked as Phishing
* Windows RDP Brute Force
* Potential Data Exfiltration



## 3. Alert Severity

Shows how dangerous the alert is.

| Severity    | Meaning                   |
| ----------- | ------------------------- |
|  Low      | Low risk                  |
|  Medium   | Moderate risk             |
|  High     | Serious risk              |
|  Critical | Urgent, investigate first |



## 4. Alert Status

Current state of the alert.

| Status      | Meaning                  |
| ----------- | ------------------------ |
| New         | Nobody is working on it  |
| In Progress | Analyst is investigating |
| Closed      | Investigation completed  |



## 5. Alert Verdict

Final investigation result.

| Verdict        | Meaning       |
| -------------- | ------------- |
| True Positive  | Real attack   |
| False Positive | Not an attack |



## 6. Alert Assignee

The analyst responsible for the alert.



## 7. Alert Description

Explains:

* Why alert was generated
* What happened
* How to investigate



## 8. Alert Fields

Extra information inside the alert.

Examples:

* Username
* Hostname
* IP Address
* Command Line
* Process Name



# Alert Prioritization

When many alerts arrive, investigate them in this order.

## Step 1: Filter Alerts

Choose only:

* New alerts
* Unassigned alerts
* Unresolved alerts

Skip alerts already assigned to other analysts.



## Step 2: Sort by Severity

Priority:

```text
Critical
    ↓
High
    ↓
Medium
    ↓
Low
```



## Step 3: Sort by Time

If two alerts have the same severity:

Investigate the **oldest alert first** because the attacker has had more time to cause damage.



# Alert Triage Process

## Step 1: Assign Alert

Assign the alert to yourself.



## Step 2: Change Status

Move status to:

```text
New
   ↓
In Progress
```



## Step 3: Read Alert

Understand:

* Alert Name
* Description
* Severity
* Affected User
* Affected Device



## Step 4: Investigate

Check:

* Who is affected?
* What happened?
* Is it suspicious?
* Review related logs/events.
* Search threat intelligence if needed.



## Step 5: Decide Verdict

Choose:

* **True Positive** → Real attack.
* **False Positive** → Benign activity.



## Step 6: Write Comments

Record:

* What you investigated.
* Evidence found.
* Why you chose the verdict.



## Step 7: Close Alert

Update:

```text
Status → Closed
```



# Alert Triage Flow

```text
Alert Generated
      │
      ▼
Assign to Yourself
      │
      ▼
Move to In Progress
      │
      ▼
Read Alert Details
      │
      ▼
Investigate
      │
      ▼
True Positive? ───────► Yes ──► Escalate / Respond
      │
      No
      ▼
False Positive
      │
      ▼
Write Comments
      │
      ▼
Close Alert
```
